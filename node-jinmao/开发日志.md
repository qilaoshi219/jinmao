### 技术细节
- 软删除：调用 `bookRepo.softDeleteCourse()`，标记 `isDeleted=true`，不删除 MinIO 文件
- 权限：仅教材所有者（`course.userId === req.userId`）可删除，非所有者返回 403
- 响应码：200（成功）、400（ID 格式无效）、401（未认证）、403（越权）、404（不存在）、500（服务端错误）
- 幂等：已删除的教材再删返回 404（因 `getCourseById` 过滤了 `isDeleted=true` 的记录）
- 参考 `GET /books/:id` 的校验模式，保持代码风格一致

## 2026-07-05 - 实现 course_pipeline.js：6阶段课程生成流水线

### 修改内容

**重写文件：`service/course_pipeline.js`（由 182 行设计文档 → 完整实现，661 行含注释）**

完整的6阶段课程生成流水线，接收课程 ID 后自动完成从教材文本到 PPT+语音+字幕的全流程生成。文件头部添加了 `// 本文件因流水线编排逻辑复杂且不可分割，特批允许超过 300 行限制` 声明。

**6个阶段概览：**

| 阶段 | 函数 | 功能 |
|------|------|------|
| Phase 1 | `phase1_fetchData` | 数据库查询课程信息 + MinIO 下载归一化 MD 文件 |
| Phase 2 | `phase2_extractAndIndex` | extractLines 提取文本 → addLineNumbers 行号索引 → getLine AI 识别章节起止行 → 创建 Chapter 记录 |
| Phase 3 | `phase3_generateCourse` | generateOutline AI 生成大纲 → 条件性 elaborateText 扩写口播稿 → 上传 outline.json 到 MinIO |
| Phase 4 | `phase4_generatePpt` | p-queue 并发5 → generateHtmlPpt AI 生成 HTML PPT → 后处理 `\n` 还原 → 上传 MinIO |
| Phase 5 | `phase5_generateTts` | p-queue 并发3 → synthesize TTS 合成 MP3+SRT → 上传 MinIO → 清理临时文件 |
| Phase 6 | `phase6_validate` | minioClient.statObject 逐文件检查完整性 → 更新 completed/partial_completed 状态 |

**核心特性：**

1. **Phase 4 & 5 并行执行**：PPT 和 TTS 在 Phase 3 完成后同时启动（`Promise.all`），互不等待，大幅缩短总耗时
2. **并发控制**：Phase 4 PPT 队列 `concurrency=5`，Phase 5 TTS 队列 `concurrency=3`，避免 API 过载
3. **容错隔离**：单个 slide 的 PPT/TTS 失败不影响其他 slide，catch 异常后继续处理下一个
4. **MinIO 独立客户端**：流水线使用独立初始化的 `minioClient`（环境变量配置），与 `upload_minio.js` 的配置互相独立
5. **临时文件清理**：每个阶段使用 `os.tmpdir()` 存储中间文件，阶段完成后自动清理
6. **详细控制台日志**：每个阶段记录开始/结束时的时间戳和耗时，格式为 `[course_pipeline][PhaseN]`

**状态机流转：**

```
idle → 1000_extracting → 1000_extracted → 1000_indexing → 1000_indexed
→ getting_line → get_line_done → course_generating → course_generated
→ ppt_generating + tts_generating (并行) → ppt_generated + tts_generated
→ data_validating → completed / partial_completed / failed
```

**新增依赖：** `p-queue@8.1.0`（并发任务队列）
