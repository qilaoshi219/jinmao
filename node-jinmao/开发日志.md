## 2026-07-04 - 安全加固：敏感配置迁移到 .env + dotenv

### 修改内容

## 2026-07-03 - 实现 extract_zip.js：压缩包解压 + 主文档查找 + 自动清理机制

### 修改内容

**重写文件：`utils/extract_zip.js`（由 12 行注释存根 → 完整实现，370 行）**

1. **新增 `validateInput(filePath)` 输入校验函数**
   - 复用 `input_validator.js` 的 `validateString()` 进行基础安全检查（空值、类型、注入攻击、Unicode 控制字符）
   - 检查文件是否存在（`fs.existsSync`）
   - 检查扩展名是否属于支持格式（.zip / .rar / .7z，大小写不敏感）
   - 返回 `{ valid, resolvedPath?, errorCode?, error? }` 结构

2. **新增 `generateTempDir()` 临时目录生成函数**
   - 使用 `crypto.randomBytes(4)` 生成 8 位随机 hex ID
   - 目录路径格式：`/data/temp/extract_<randomId>/`
   - 递归创建目录（含根目录 `/data/temp/`）
   - 返回 `{ success, dirPath?, errorCode?, error? }`

3. **新增 `executeExtract(filePath, extractDir)` 解压执行函数**
   - 使用 `child_process.exec` 调用项目内置 `tools/7z/7za.exe`
   - 命令格式：`7za.exe x <archive> -o<dir> -y`
   - 设置 5 分钟超时（应对大文件解压）
   - 容错处理：即使 7z 返回非零退出码，若输出包含 "Everything is Ok" 仍视为成功
   - 返回 Promise

4. **新增 `findMainDoc(extractDir)` + `walkDir(dirPath)` 主文档查找函数**
   - 递归遍历解压目录所有文件
   - 筛选 `.md` 扩展名文件
   - 返回第一个找到的 .md 文件路径，未找到返回 null
   - 不输出逐文件日志，避免控制台刷屏

5. **新增 `extractZip(filePath, timeoutMs?)` 核心入口异步函数**
   - 完整流程：输入校验 → 生成临时目录 → 7z 解压 → 查找主文档 → 注册超时清理 → 返回结果
   - 解压失败时自动清理已创建的临时目录
   - 第二个参数 `timeoutMs` 控制超时清理时间（默认 30 分钟，传 0 不启用）
   - 错误码体系：

   | code | 含义 |
   |------|------|
   | `200` | 解压成功，找到 .md 主文档，返回 `extractDir` 和 `mainDocPath` |
   | `201` | 解压成功，但未找到 .md 文件，仅返回 `extractDir` |
   | `400` | 输入参数不合法（空值/类型错误/不支持的压缩格式/cleanUp非安全路径） |
   | `404` | 压缩包文件不存在 |
   | `500` | 解压过程失败（7z 工具不存在/解压命令执行失败/临时目录创建失败） |

6. **新增 `cleanUp(extractDir)` 目录清理函数**
   - 安全检查：仅允许删除 `/data/temp/` 下的目录，防止误删
   - 调用前自动取消对应的超时定时器（避免重复清理）
   - 使用 `Map<dir, timerId>` 管理定时器映射
   - 返回 `{ code: 200, message? }` 或 `{ code: 400, message? }`

7. **新增 `removeDirSync(dirPath)` 递归删除辅助函数**
   - 使用 `fs.rmSync` 递归强制删除

8. **新增超时自动清理机制**
   - `DEFAULT_TIMEOUT_MS = 30 * 60 * 1000`（30 分钟）
   - 解压成功后自动注册 `setTimeout`，到期自动调用 `cleanUp`
   - `cleanUp` 被显式调用时取消对应定时器
   - 防止解压目录被占用过久导致硬盘占满

9. **详细的控制台输出**
   - 使用 `[extract_zip]` 前缀，二级标记 `[validateInput]` / `[generateTempDir]` / `[executeExtract]` / `[findMainDoc]` / `[extractZip]` / `[cleanUp]` / `[removeDirSync]`
   - 复用 `input_validator.js` 的注入检测日志（`[extract_zip][validateString]`）
   - 解压时输出 7z 统计摘要（最后 3 行），避免刷屏

**新增目录：`tools/7z/`**
- 下载并内置 7-Zip 命令行工具 `7za.exe`（v9.20）
- 支持 .zip / .rar / .7z 格式的解压
- 项目部署时无需额外安装 7-Zip

## 2026-07-02 - 实现 text_tts.js：火山引擎 TTS 文本转语音 + SRT 字幕生成服务

### 修改内容

**新增文件：`service/text_tts.js`**

1. **新增 `validateInput(text)` 输入校验函数**
   - 空值检查：拦截 text 为 null / undefined / 空字符串
   - 类型检查：text 必须为 string 类型
   - 长度限制检查：最大 1024 字符（火山引擎 TTS 单次合成限制）
   - 返回 `{ valid, errorCode, error }` 结构

2. **新增 `synthesize(text)` 核心异步函数**
   - 流程：输入校验 → 加载配置 → 调用 TTS API → 写入文件 → 返回路径
   - 采用火山引擎 HTTP Chunked 单向流式接口（`/api/v3/tts/unidirectional`）
   - 使用 Node.js 内置 `https` 模块，无需额外依赖
   - 流式接收响应，逐行解析 JSON：
     - `code: 0` + `data` 字段 → 音频 base64 数据，追加到缓冲区
     - `code: 0` + `sentence` 字段 → 字幕数据，收集到列表
     - `code: 20000000` → 合成结束，记录用量
   - 启用字幕功能（`enable_subtitle: true`），需要 TTS 2.0 音色
   - 音频数据 base64 解码后写入 MP3 文件
   - 字幕 words 按标点分句生成 SRT 文件
   - 请求超时设置：30 秒
   - 错误码体系：

   | code | 含义 |
   |------|------|
   | `200` | 合成成功，返回 mp3Path 和 srtPath |
   | `400` | 输入参数不合法（空文本/非字符串类型/超长） |
   | `500` | TTS API 调用失败（网络错误/连接失败/写入失败） |
   | `502` | API 返回数据解析失败（JSON 解析错误） |
   | `503` | API 返回格式不符合预期（缺少音频数据） |
   | `504` | 配置加载失败（配置文件不存在/格式错误/密钥未填写） |

3. **新增 `generateSrtContent(sentenceList)` SRT 字幕生成函数**
   - 从 API 返回的 `sentence.words` 逐词遍历
   - 分句规则：遇到以句号、逗号、分号、感叹号、问号、冒号 结尾的 word 时输出一条 SRT 条目
   - 末尾无标点的剩余文本作为最后一个条目
   - 时间格式：`HH:MM:SS,mmm`（从秒浮点数转换）
   - 序号从 1 开始递增

4. **新增 `loadConfig()` 配置文件读取函数**
   - 检查配置文件是否存在
   - JSON 解析与节点校验
   - 检查 APP_ID 和 ACCESS_KEY 是否已填
   - 返回 `{ success, config?, errorCode?, error? }` 结构

5. **新增 `formatSrtTime(seconds)` / `generateTimestamp()` 辅助函数**

6. **详细的控制台输出**
   - 使用 `[text_tts]` 前缀，二级标记 `[validateInput]` / `[loadConfig]` / `[callTtsApi]` / `[generateSrtContent]` / `[synthesize]`
   - 信息级日志：输入验证、配置加载、API 请求、音频/字幕数据统计、文件保存
   - 错误级日志：参数校验失败、配置异常、API 错误、解析失败、写入失败
