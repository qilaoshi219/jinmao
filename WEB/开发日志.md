## 2026-07-06 - 登录页按 design-spec 规范全面重构

### 修改原因
登录页原为纯手写 HTML + Tailwind 原子类，没有任何暗黑模式适配，且违反新制定的 design-spec 设计规范约 50+ 处（文字灰阶、圆角不一致、过渡时间不统一、无 dark 双轨、手写组件等）。

### 改造方案
1. **激活 Element Plus**：配置 vite 按需自动导入 + main.js 暗黑 CSS 变量
2. **模板重构**：手写 `<input>` → `<el-input>`、手写 `<button>` → `<el-button>`、手写消息 div → `<el-alert>`
3. **逻辑优化**：`isLoading` 拆分为 `isSending` / `isSubmitting` 独立 loading 状态
4. **响应式适配**：全宽容器 + `sm:`/`lg:`/`2xl:` 响应式 padding

### 修改文件

| 文件 | 操作 | 说明 |
|------|------|------|
| `vite.config.js` | 修改 | 添加 AutoImport + Components 插件（ElementPlusResolver 按需自动导入） |
| `src/main.js` | 修改 | 导入 `element-plus/theme-chalk/dark/css-vars.css`（暗黑模式支持） |
| `src/pages/login/index.vue` | 重写 | 全面替换为 Element Plus 组件 + dark: 双轨 + 响应式断点 |
| `src/pages/login/script.js` | 重写 | isLoading 拆分为 isSending/isSubmitting，新增 isProcessing 计算属性 |

### 规范符合度

| 规则 | 改造前违规 | 改造后 |

## 2026-07-06 - 新增暗黑模式支持与前端规范手册

### 修改原因
前端缺乏暗黑模式支持，所有样式为亮色硬编码。需要一个成熟的日间/夜间模式切换方案，避免手搓代码。

### 技术方案
采用 **三层架构组合方案**（全部基于成熟开源方案，非自研）：

| 层级 | 技术 | 职责 |
|------|------|------|
| 状态管理 | `@vueuse/core` - `useDark` | 响应式状态、localStorage 持久化、系统偏好检测 |
| 样式引擎 | Tailwind CSS v4 - `dark:` 变体（class 策略） | 原子级样式切换 |
| 基础层 | CSS 自定义变量 + `prefers-color-scheme` fallback | 全局样式 + JS 不可用时的兜底 |

### 新增文件

| 文件 | 说明 |
|------|------|
| `src/composables/useTheme.js` | 封装 VueUse 的 useDark + useToggle，导出 isDark 和 toggleTheme |
| `src/styles/tokens.css` | 定义 :root 和 .dark 两套 CSS 变量，处理 Tailwind 覆盖不到的场景 |
| `docs/前端暗黑模式规范手册.md` | 前端暗黑模式开发规范，含颜色映射表、Checklist、FAQ |

### 修改文件

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/styles/index.css` | 修改 | 添加 `@custom-variant dark` 启用 Tailwind class 策略；导入 tokens.css；body 使用 CSS 变量 |
| `src/main.js` | 修改 | 更新样式导入注释，说明包含暗黑模式配置 |
| `src/App.vue` | 修改 | 所有颜色类添加 dark: 对应；导入 useTheme；右上角添加主题切换演示按钮 |
| `package.json` | 修改 | 新增依赖 `@vueuse/core`（通过 `npm install` 自动更新） |

### 关键决策

- **选择 VueUse useDark 而非自研**：状态管理、持久化、系统检测全部内置，3 行代码搞定
- **使用 Tailwind class 策略（非 media）**：允许用户手动切换，体验更好
- **规范手册不强制改造已有页面**：作为新页面开发准则，已有页面可逐步改造
- **使用 light/dark 二进制切换**：暂不需要 system/auto 三态模式（按需可扩展为 useColorMode）

### 依赖变更

- 新增：`@vueuse/core`（^13）

## 2026-07-06 - 代码审查修复：拆分 LoginPage.vue 为独立文件

### 修改原因
代码审查指出 JS、CSS、HTML 混合在同一 .vue 文件中会造成代码维护灾难。本次修复将页面拆分为两个独立文件，实现 Template(HTML) 和 Script(JS) 的完全分离。

### 文件拆分结构

| 文件 | 角色 | 内容 |
|------|------|------|
| `LoginPage.vue` | 视图入口 | 纯 template HTML 结构 + `<script src>` 引用 |
| `LoginPage.script.js` | 业务逻辑 | `export default { setup() }` 包含所有响应式数据和方法 |

### 架构说明
- LoginPage.vue 通过 `<script src="./LoginPage.script.js">` 引用外部逻辑文件
- LoginPage.script.js 通过 `export default { setup() { ... return { ... } } }` 导出所有变量/方法
- CSS 全部使用 Tailwind 原子类（在 template 中以 class 形式存在，不由独立文件管理）
- 模板中每个 HTML 区域都有注释说明该区域的绑定和功能
- script.js 中每个变量/函数都有 JSDoc 说明输入、输出、副作用

### 修改文件

| 文件 | 说明 |
|------|------|
| `src/pages/LoginPage.vue` | 重写为纯模板入口，增加架构说明和逐区域注释 |
| `src/pages/LoginPage.script.js` | 新增，包含全部业务逻辑（~435行），分十大章节标注 |

### 技术要点
- `<script setup src="...">` 不被 Vue 编译器支持，改用 `<script src="...">` + `export default { setup() }`
- setup() 返回值自动暴露给模板，与 `<script setup>` 效果等同

## 2026-07-06 - 新增登录注册页面

### 修改内容

新增邮箱验证码登录/注册页面，使用后端已有的 `smtpcode` 和 `login` API。登录与注册统一入口，后端自动判断新用户（注册）还是老用户（登录）。不引入 vue-router，在 App.vue 中通过 `isLoggedIn` 状态做条件渲染切换页面。

### 新增文件

| 文件 | 说明 |
|------|------|
| `src/pages/LoginPage.vue` | 登录注册页面：邮箱输入、发送验证码（60s倒计时）、验证码输入、登录/注册按钮、状态提示消息 |

### 修改文件

| 文件 | 说明 |
|------|------|
| `src/App.vue` | 添加条件渲染：未登录显示 LoginPage，已登录显示主页 + 用户信息 + 登出按钮 |

### 技术要点

- 登录成功/失败后 UI 自动切换，无需手动跳转（Vue 响应式驱动）
- 验证码发送后自动聚焦验证码输入框，支持回车键快捷操作
- 401 未授权时 client.js 跳转 `/login`，Vite fallback 到 index.html 后重新显示登录页
- 前端 60s 倒计时防止重复发送，后端独立频率限制（5分钟最多3次）

## 2026-07-05 - WEB 前端基础设施搭建

### 修改内容

在 `WEB/` 目录下从零搭建 Vue 3 + Vite + Tailwind CSS + Pinia + Axios 前端项目基础设施。不包含任何页面文件，仅搭建 API 层、状态管理、工具函数等核心基础设施。

### 技术选型

| 决策项 | 选择 | 原因 |
|--------|------|------|
| 前端框架 | Vue 3 + Vite | 国内社区活跃，中文文档完善，SFC 直观 |
| 样式方案 | Tailwind CSS v4 | 原子化 CSS，打包体积小，@tailwindcss/vite 集成简单 |
| 状态管理 | Pinia | Vue 3 官方推荐，Composition API 风格 |
| HTTP 客户端 | Axios | 拦截器支持 Token 注入和 401 统一处理 |
| 端口 | 前端 30000，后端 8888 | 30000+ 范围，前后端分离 |

### 新增文件

| 文件 | 说明 |
|------|------|
| `package.json` | 项目依赖（vue、axios、pinia、tailwindcss、@tailwindcss/vite） |
| `vite.config.js` | Vite 配置：端口 30000、/api 代理到 localhost:8888、strictPort 启用 |
| `index.html` | HTML 入口，lang=zh-CN |
| `src/main.js` | Vue 应用入口：createApp + Pinia + 全局样式 + 挂载 |
| `src/App.vue` | 根组件占位页面（展示技术栈标签和端口信息） |
| `src/styles/index.css` | Tailwind CSS 指令入口 |
| `src/api/client.js` | Axios 实例：请求拦截器自动注入 Bearer Token，响应拦截器 401 跳登录 |
| `src/api/auth.js` | 认证 API：sendCode、login、getProfile、updateProfile |
| `src/api/books.js` | 教材 API：uploadBook（multipart 10min 超时）、listBooks、getBookDetail、getBookStatus |
| `src/stores/auth.js` | Pinia auth Store：token/user 状态，login/fetchProfile/logout 方法 |
| `src/utils/storage.js` | localStorage 封装：KEYS 常量，Token 存取 + 通用 get/set/remove |
| `start.ps1` | 前端快速启动脚本（端口检测 → 依赖检查 → 启动 dev server） |
| `FILE.md` | 前端文件索引 |
| `开发日志.md` | 本文档 |

### 前后端通信架构

```
开发模式：
  浏览器 → localhost:30000 (Vite Dev Server)
            ├── /api/*  → proxy → localhost:8888 (Express 后端)
            └── /*      → Vite 处理（静态资源 + HMR）

生产模式（后续实施）：
  浏览器 → localhost:30080 (Express)
            ├── /api/v1/* → 后端路由
            ├── /assets/* → 前端静态资源 (express.static)
            └── /*        → index.html (SPA fallback)
```
